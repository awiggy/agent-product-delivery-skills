# AI 产品交付 Skills

把 AI 产品从点子推进到可验收的业务闭环：先推导架构与技术适配，再实现 Agent 交互，最后检查发布与回滚条件。

这是给 AI 编程助手使用的 **四个独立 Skill**，不是应用脚手架、云平台客户端或一键上线工具。每个 Skill 可单独使用；不需要一次加载整个仓库。

## 选择入口

| 你的任务 | Skill | 主要产出 |
| --- | --- | --- |
| 从点子/PRD 判断是否需要 Agent，设计最小架构 | [agent-blueprint](skills/agent-blueprint/SKILL.md) | 需求事实、Agent/工作流判断、组件选型、权限和验收方案 |
| 从 PRD 开始，或继续已有 AI 产品的一个业务阶段 | [agent-mvp-delivery](skills/agent-mvp-delivery/SKILL.md) | 技术适配说明、最小业务闭环、测试证据、待验收项 |
| 构建或完善 Agent 的任务型前端 | [agent-frontend-delivery](skills/agent-frontend-delivery/SKILL.md) | 页面状态矩阵、接口契约、恢复交互、浏览器验收 |
| 判断能否上线，准备发布或执行已授权的部署 | [agent-release-readiness](skills/agent-release-readiness/SKILL.md) | 发布检查、数据恢复方案、发布验证、回滚条件 |

## 为什么分开

架构、开发、交互和发布的输入、风险与交付证据不同。Blueprint 负责决定“构建什么、为何这样设计”，MVP 负责“实现并验证这一阶段”。分开后，已有 Vue 项目不用为了套模板迁移到 Next.js；前端断线不会被误判为后端失败；发布评估也不会自动创建付费云资源。

本套件关注四件事：保留合理的现有技术栈、按完整业务链路推进、区分 mock 与真实验证、让失败和恢复路径可以验收。它不承诺自动生成可直接上线的产品。

## 如何使用

从 `skills/` 中选择需要的目录，将整个目录交给支持 `SKILL.md` 的助手或其技能安装器；保持目录内的 `references/`、`assets/` 和 `agents/` 相对路径。不要将仓库根目录当成一个 Skill。具体安装位置由所用助手决定，本仓库不自动修改本地配置。

可直接把入口文件路径连同任务交给助手；安装后支持命名调用的助手可使用以下示例：

```text
使用 $agent-blueprint。根据我的想法或 PRD，判断是否需要 Agent，
给出最小组件、工具权限和验收方案。目前只做架构，不生成代码、不部署。
```

Blueprint 的准备资料、三类场景、预期输出与边界见 [完整使用说明](docs/agent-blueprint-usage.md)。

```text
使用 $agent-mvp-delivery。基于现有项目和 PRD，实现报销申请到审批的最小闭环。
保留现有技术栈；先说明本阶段范围，再实现并区分 mock 与真实接口验收。
```

```text
使用 $agent-frontend-delivery。完善长任务页面：刷新后恢复任务，断线可重连，
重试不重复创建付费任务。先核对现有接口，不要伪造后端已经支持取消。
```

```text
使用 $agent-release-readiness。只检查是否具备上线条件，不部署、不购买资源。
重点检查鉴权、数据持久化、备份恢复和版本回滚，列出已验证与未验证项。
```

## 按需读取

入口包含任务边界和工作流程；遇到该阶段的具体问题时才读对应参考。模板仅在需要产出文档时读取。没有总控 Skill 要求预读四套规则，没有依赖其他 Skill 才能工作的隐藏链接。

每个 Skill 都可以输出下一阶段的输入，但不会自动启动下一阶段。用户只要求评估时不改代码；只要求本地开发时不部署。

## 依赖与限制

- Skill 本身为 Markdown 与 YAML，无需模型密钥或云账号才能阅读。
- 执行开发任务需要目标项目自身的语言、测试和浏览器环境；本套件不捆绑这些工具。
- 真实模型验收需要目标项目的服务配置与调用授权；没有条件时标记“未验证”，不以 mock 代替。
- 部署操作需已选定平台及权限；CLI、区域、价格与资源限制必须在执行前查阅当时的官方文档，不内置易过期命令。
- 目前为初版：结构校验和离线场景审查见 [验证记录](docs/validation.md)，尚非生产环境验证认证。

## 设计与范围

四个 Skill 按架构、开发、交互和发布分别组织，详细取舍见 [设计说明](docs/design.md)。各入口独立使用，按需读取参考，不自动扩展任务范围。
