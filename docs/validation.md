# 初版验证记录

日期：2026-09-21。验证范围：Skill 包结构、参考路由与编写者离线场景审查。没有运行真实产品开发、调用付费模型或部署云资源。

## 可重复的包检查

在仓库根目录执行（需要 Node.js）：

```sh
node scripts/check-package.mjs
```

检查四套独立入口、名称与目录一致、元信息调用名称、相对链接有效、Skill 无目录外依赖及入口长度预算。脚本自身检查目录边界的正反例。它不验证模型行为，也不解析所有可能的 Markdown 语法。

另外，四个 Skill 均已通过本次创建环境提供的 `skill-creator/scripts/quick_validate.py` 校验。该外部校验器不是本仓库运行依赖；检查命名、YAML frontmatter 和未完成占位等。

## 编写者离线情境审查

以下为对指令决策路径的人工审查，不是独立 Agent 测试或端到端实测。

| 情境输入 | 根据当前指令应采取的决策 | 规则位置 |
| --- | --- | --- |
| 已有 Vue + Express，只新增审批闭环 | 保留技术栈，新增最小业务路径，不换 Next.js/FastAPI | MVP 的 adaptation |
| 模型密钥未配置，但 mock 测试通过 | mock 已通过、真实服务未验证，不报告完整验收成功 | MVP 的 runtime-and-acceptance |
| UI 是 Agent 人工审批的一部分 | 先做前后端纵向切片，不等待整个后端完成 | MVP 入口 |
| 流断开、用户要求继续 | 查原 task ID 状态后恢复，不重建付费任务 | 前端的 task-contract |
| 用户只要求修正导航位置 | 共用布局约束，仅修相关样式，不新增整个任务系统 | 前端入口及 visual-and-testing |
| 取消 API 尚未实现 | 列后端缺口，不用按钮动画伪造取消成功 | 前端入口 |
| 只检查能否上线，明确不要上云 | 只读检查并列阻塞，不创建资源 | 发布入口 |
| 数据只在临时磁盘，有预留实例与定期备份 | 不能证明持久可靠；检查一致性与隔离恢复演练 | 发布的 data-and-rollback |
| 首页 HTTP 200 但部署版本不明、API 失败 | 不判为上线成功，验证版本和真实业务 | 发布的 release-gates |
| 权限不足、CLI 提示可授管理员权限 | 定位缺失的最小权限，不默认 FullAccess | 发布的 provider-execution |
| 需要破坏性数据迁移 | 确认独立授权与备份/恢复策略，不视作普通代码发布 | 发布入口及 data-and-rollback |

## Blueprint 增补审查

本次为编写者对规则的离线推演，不是独立执行者测试：

| 输入 | 预期决策 |
| --- | --- |
| 固定审批流程，希望“做成 Agent” | 比较普通工作流与局部模型能力，不默认无限工具循环 |
| 不允许文件出域，却要求全文交外部模型 | 指出冲突，等待关键取舍，不偷偷外传 |
| 已有架构批准，只要求按原方案实现 | 不重复要求批准，不额外部署 |
| 只读子 Agent 获得任意 Shell | 识别提示词不足以保证只读，要求执行端边界 |
| 缺少预算/实际效果数据 | 明确假设与待测标准，不编造生产级保证 |

本包未包含或执行配套 Agent 示例代码，不能将结构检查当作运行时端到端测试的证据。
