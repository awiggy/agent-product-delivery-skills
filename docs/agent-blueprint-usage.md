# Agent Blueprint 使用说明

## 它解决什么问题

当你有点子或 PRD，但不知道是否需要 Agent、要哪些组件、权限怎么划分时使用。它产出可交给开发阶段的架构方案，不是自动运行的 Agent。

能力与使用边界见 [功能范围](../skills/agent-blueprint/references/scope.md)。

## 需要准备什么

- 一句话需求或已有 PRD；已有代码则提供项目路径与允许读取范围。
- 用户、输入/输出、不可触碰的数据或操作；不知道的可以明确说不知道。
- 有哪些约束：现有框架、模型或数据出域要求、预算、只做方案还是也允许实现。

不用先申请云账号或提供模型密钥。架构输出由你使用的 AI 助手生成，本包不含独立模型程序。

## 加载方式

从 [Skill 目录](../skills/agent-blueprint/SKILL.md) 进入；将完整 `skills/agent-blueprint/` 目录交给你的助手或技能安装器，保留引用文件与 LICENSE。具体安装方式以助手为准。

未安装时也可明确要求助手读取这个入口文件及当前任务需要的参考，再根据你的需求执行。不要把本仓库根目录当作一个 Skill 安装。

## 三种调用示例

### 只有一个想法

```text
使用 $agent-blueprint。我想做一个帮助客服整理工单的助手，还没有 PRD。
请先澄清关键问题，再给最小架构；目前只做方案，不写代码、不调用工单系统。
```

预期：先弄清用户、数据、结果和禁区；不默认创建 Agent 团队或连接公司系统。

### 已有 PRD

```text
使用 $agent-blueprint。根据附件 PRD，判断固定工作流还是 Agent 更合适。
列出五要素、组件取舍、工具权限与验收计划。不自动执行部署。
```

预期：可以得出“不需要动态 Agent”的结论；方案中的计划与已验证事实分开。

### 已有产品要扩展

```text
使用 $agent-blueprint。项目已经使用 Vue 和 Express，我只想增加异步资料分析。
保留现有栈，分析需要新增的任务状态、权限和恢复机制，先给增量方案。
```

预期：检查已有接口和数据流，不为了匹配模板重建整个项目。

## 会拿到什么

目标与范围、事实/假设/待确认项、Agent/工作流判断、工具/知识/观察/行动/权限五要素、必要组件与数据流、权限和预算边界、验收计划、实现交接。简单问题可以简短交付，不机械生成全套长文档。

## 与其他三个 Skill 如何配合

架构没想清楚时先用 Blueprint；方案已明确并要求实现时，使用 `agent-mvp-delivery`。界面交互使用 `agent-frontend-delivery`；上线准备使用 `agent-release-readiness`。这是选择顺序，不是自动执行链，也不是四个必须同时安装的依赖。

## 不包含与验证程度

不包含 17 类机制的配套实现、自动脚手架或第三方 SDK。不会因为读取 Skill 就执行 Shell、调用付费模型或部署。

已经检查入口结构与本地链接，并做编写者离线场景审查；尚未完成独立 Agent 行为评测和真实产品端到端验收。请先在非生产任务中试用，不能把“方案完整”理解为“产品已通过生产验收”。
