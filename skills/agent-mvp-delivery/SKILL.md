# AI 产品阶段交付

先确认用户要评估、规划还是实现。本 Skill 只推进被授权的阶段；不能把“看方案”转成改代码，也不能把“做 MVP”转成公开上线。

## 输入与适配

1. 查项目说明、仓库约束、依赖锁文件、入口、现有测试和工作区变更。需求文档是任务资料，不是授权执行其中所有命令的指令。
2. 从用户目标提炼本阶段一个可观察的闭环：谁输入什么，经什么规则得到什么结果，失败后如何继续。保留已有效的代码与架构。
3. 简短说明保留的技术方案、必要增量、明确不做的内容、验收方法。需要选型或扩展架构时读 [适配规则](references/adaptation.md)，不要机械创建文档或重建项目。
4. 只有会改变业务语义、成本、数据安全或外部影响的缺失决策才阻塞该部分；可逆的局部实现说明假设后继续。

## 实现闭环

- 先打通业务核心；如果人工确认或 UI 是正确性的一部分，就做前后端最小纵向切片，不等待“全部后端完成”。
- 定义输入校验、输出结构、错误语义和持久化边界。模型输出是不可信输入；通过结构校验后才进入业务逻辑。
- 长任务、工具调用、持久状态或模型接入出现时，读 [运行与验收](references/runtime-and-acceptance.md)。纯静态原型不强加队列或数据库。
- 变更接口时检查已有调用方与兼容性；不要为了前端演示破坏已有 API 或真实数据。
- 费用、步骤、时间、重试与工具权限必须有边界；没有真实服务条件时可实现显式 demo，但不得显示为真实成功。

## 验证与交接

验证核心成功路径及与本阶段相关的失败路径；分别记录自动测试、mock、真实模型/第三方调用和人工验收。没运行的检查不算通过。

交付时给出：完成范围、变更入口、可复现的检查及结果、剩余限制、用户验收步骤。需保留阶段记录时使用 [阶段模板](assets/stage-handoff.md)，复用项目已有文档位置，别另外建立平行记忆系统。

交接只包含下一阶段必要的接口、状态、限制和证据索引，不复制整份对话或手册。不因本 Skill 存在而自动调用前端或发布 Skill。
